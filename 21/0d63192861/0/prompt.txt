### Add

1. Edit `feed_urls.json` to add the entry/entries. Use `max_articles` for high-frequency feeds (>10/day; typical 5–20).
2. Test the new feeds (see Testing).
3. Fix any failures before keeping them.
4. Sync.

### Remove

1. Remove the entry/entries from `feed_urls.json`.
2. Sync.

### Test

Run this script via `uv run python - <<'EOF' ... EOF`, replacing `names` with the feeds to test (or all feeds if testing everything):

```python
import json, sys, urllib.request

names = {"Feed Name"}  # replace or set to None to test all

with open("/Users/eamon/code/rss-email/feed_urls.json") as f:
    all_feeds = json.load(f)["feeds"]

feeds = all_feeds if names is None else [x for x in all_feeds if x["name"] in names]
headers = {"User-Agent": "Mozilla/5.0 (compatible; RSS reader)"}
ok, warn, fail = [], [], []

for feed in feeds:
    name, url = feed["name"], feed["url"]
    try:
        req = urllib.request.Request(url, headers=headers)
        with urllib.request.urlopen(req, timeout=10) as r:
            data = r.read(512)
        is_xml = any(t in data[:300] for t in [b"<rss", b"<feed", b"<?xml"])
        if is_xml:
            print(f"  ✅ {name}")
            ok.append(name)
        else:
            print(f"  ⚠️  {name} — not XML: {data[:100]}")
            warn.append(name)
    except Exception as e:
        print(f"  ❌ {name} — {e}")
        fail.append(name)

print(f"\n{len(ok)} ok, {len(warn)} warning, {len(fail)} failed")
sys.exit(1 if fail or warn else 0)
```

**Failure patterns and fixes:**

- **404**: Feed moved — try `/feed`, `/rss`, `/atom.xml`; check for Substack/Ghost migration; look for `<link rel="alternate">` on homepage
- **403 / "Just a moment..."**: Cloudflare bot protection — feed inaccessible, remove it
- **200 but HTML**: Wrong URL or login wall — search for the real feed path
