## 1. `podcast_generator.py` (627 lines)
- **Prompt:** `PODCAST_PROMPT` (L32-74) is for "Eamon's Daily Tech News", 5-10 minutes, hosts Marco and Joanna.
  - It forbids brackets, stage directions and announcer intro/outro, and ends with "Articles to cover:".
  - It asks for "Marco:" / "Joanna:" line prefixes.
  - It says "grouped by theme" and "conclude with lighter articles".
- **Prompt builder:** `create_podcast_script_prompt(articles: List[Dict]) -&gt; str` (L293-309) appends only `Title:` and `Description:` for each article, separated by `---`. Sources and links are not included.
- **Model:**
  - `generate_script(articles) -&gt; Optional[str]` (L313-347) is a direct, synchronous call to `anthropic.Anthropic(api_key=...).messages.create`.
  - Model is `CLAUDE_MODEL` or `DEFAULT_CLAUDE_MODEL`, which is `claude-haiku-4-5` (L23-26 and `models.py`). `max_tokens` is `CLAUDE_MAX_TOKENS`, default 4000.
  - It isn't used in production; the production path is the batch flow below. It is only covered by tests.
- **Speaker parsing:** `parse_speaker_segments(script) -&gt; List[Tuple[str, str]]` (L95-142).
  - Regex line-prefix match, case-insensitive. Default speaker is Marco; unlabelled lines continue the current speaker; blank lines are skipped.
- **Voices and SSML:**
  - Constants are at L77-88: `MARCO_VOICE="Matthew"`, `JOANNA_VOICE="Joanna"`, rates 120% and 122%.
  - `enhance_text_with_ssml(text, speaker) -&gt; str` (L186-229) XML-escapes the text, adds `&lt;break&gt;` tags after punctuation, and wraps it in `&lt;speak&gt;&lt;prosody rate&gt;`.
- **Chunking:**
  - `chunk_text(text, max_chars=3000)` (L146) and `chunk_ssml_text(ssml_text, speaker, max_chars)` (L233) split at sentence boundaries.
  - `chunk_ssml_text` re-wraps each chunk in valid SSML. `POLLY_NEURAL_CHAR_LIMIT` is 3000.
- **Synthesis:** `synthesize_speech(script) -&gt; Optional[bytes]` (L351-407).
  - Per segment it calls `polly.synthesize_speech` with `Engine="neural"`, mp3 output, `TextType=ssml`.
  - It concatenates the raw mp3 bytes, and returns `None` on any `ClientError` or if there are no segments.
- **S3 and domain:**
  - `upload_to_s3(bucket, key, data, content_type) -&gt; bool` (L411).
  - `get_cloudfront_domain(parameter_name) -&gt; Optional[str]` (L428).
- **Feed update:** `update_podcast_feed(bucket, audio_url, title, description, pub_date, *, audio_size, cloudfront_domain=None, distribution_id=None) -&gt; bool` (L495-616).
  - It reads `podcasts/feed.xml`, rebuilds the whole RSS 2.0 document with iTunes tags, puts the new item first and keeps 9 old items (10 total, L585), then uploads.
  - Channel metadata and the pretty-printing are at L541-594.
  - The item's guid is the audio URL. The enclosure is `audio/mpeg` with `length=audio_size`.
- **Invalidation:** `invalidate_cloudfront_cache(distribution_id, paths) -&gt; bool` (L454-491), called from L607-611 with `['/podcasts/feed.xml']`.
- **Handlers:** the old single Lambda handler is gone (L619-622). Production uses three Lambdas:
  - `submit_podcast_batch.py` (L21-105): reads the same S3 `articles.json`, runs `filter_items` since the podcast's own `PODCAST_LAST_RUN_PARAMETER`, sorts newest first and takes the top 100. It builds the prompt and submits a one-request Anthropic Message Batch (`custom_id="podcast-script"`, `max_tokens=4000`).
  - `check_podcast_batch_status.py` (90 lines): polls the batch.
  - `retrieve_and_generate_podcast.py` (L21-126):
    1. Fetches the batch script (L54-66).
    2. Runs `synthesize_speech` (L69).
    3. Uploads to `podcasts/episodes/rss-digest-{ts}.mp3` (L75-81).
    4. Builds the URL from the CloudFront domain SSM parameter (L84-91).
    5. Runs `update_podcast_feed` with title "RSS Digest - {date}" and a static description (L94-110).
    6. Calls `set_last_run` (L113).

## 2. Invocation (`lib/rss_lambda_stack.ts`)
- **Schedule:** the `dailyNewsletterRule` cron is `30 7 * * 2-6` (L560-562). It targets the Step Functions state machine `DailyRSSNewsletterWorkflow` (L536-546), with a 25-hour timeout.
- **Workflow:** `retrieveArticlesTask` → `Parallel` ("Process Email and Podcast", L525-529) → success.
  - The email branch is isolated with its own catch.
  - The podcast branch (L461-523) runs Submit Podcast Batch → Check Status → a 60s wait while polling, a 5m wait after 5 polls (`POLL_BACKOFF_THRESHOLD`, L380) → Retrieve and Generate Podcast. It is isolated with its own catch that sends an SNS notification.
  - So the podcast branch runs in parallel with the email branch, and nothing is shared between them.

## 3. The brief
- **Models** (`models.py`):
  - `MustRead(id, why)` (L200).
  - `BriefTheme(theme, signal_strength HIGH|STRATEGIC|GENERAL, tldr, top_articles: ids, relevance_to_reader)` (L163).
  - `BriefCategory(week_verdict, themes)` (L177).
  - `CrossCuttingSignal(signal, categories_involved, implication)` (L184).
  - `PersonalBlock(top_stories, summary)` (L192).
  - `BriefSynthesis(must_read, categories: Dict[str, BriefCategory], cross_cutting, personal: Optional)` (L211-217).
- **Result container:** `BriefResult(NamedTuple)` (`brief_generator.py` L911) has `html`, `synthesis: BriefSynthesis` and `article_index: Dict[id, {title, url, source, comments}]`. The index lets a consumer resolve the ids in `top_articles` and `must_read` to titles and sources.
- **Entry points:** `generate_brief_full(categories, *, date, article_count, client, previous_context, seen_links) -&gt; Optional[BriefResult]` (L919-969). `generate_brief` (L972) returns the HTML only.
- **Where a podcast could consume it:** `_maybe_send_brief` (`retrieve_and_send_email.py` L146-190). `result` is available at L174-181, after the SES send (L183) and the memory save (L186-188). It is wrapped in a swallow-all `except` (L189), so a podcast hook there would be best-effort.
  - Hooking in there means the podcast would live in the retrieve-and-send Lambda, which has a 600s timeout.
  - Polly synthesis and the S3 and CloudFront steps would need to move into, or be called from, that Lambda. It already shares the role that has Polly and CloudFront permissions.
  - It runs only for days with themed or personal content; it returns `None` if disabled, empty, or synthesis fails.
- **Model call:** `synthesize` (L388+) makes a streamed call, `client.beta.messages.stream`, with model `claude-opus-5-5`, `max_tokens=32000`, `output_config={"effort": ...}`, the refusal-fallback beta, and 2 attempts. It reads `CLAUDE_API_TIMEOUT` (240 in the stack).
- **Brief input:** `build_synthesis_input` (L197-253) keeps only themed and personal categories, drops sponsored and previously-seen links, and assigns numeric ids.
- **Prompt conventions** (`brief_prompt.py`):
  - A `PROMPT_TEMPLATE` with `{PLACEHOLDER}` fields substituted via `str.replace`, so the literal JSON braces survive.
  - Separate rule constants (`MAJOR_STORY_RULE`, `SOURCE_RULE`, `FIDELITY_RULE`, `PREVIOUS_CONTEXT_RULE`).
  - Output is JSON only, with numeric-id citations kept out of prose fields.
- **`brief_config.json`:** `model` claude-opus-5-5, `effort` medium, `reader_profile`, `personal_interests`, `must_read_min` 5 / `max` 8, `max_themes_per_category` 3, `max_total_themes` 12, `cross_cutting_max` 3.
  - `themed_categories`: AI/ML, Technology, Cybersecurity, Business, Programming, Politics.
  - `personal_categories`: Cycling.
  - Prioritised and deprioritised source lists.
- **Memory:** `brief_memory.py` has `DEFAULT_MEMORY_KEY="brief-memory/memory.json"`, a 14-day window, and `render_previous_context`. The models are `BriefMemoryDay` and `BriefMemoryTheme`.
